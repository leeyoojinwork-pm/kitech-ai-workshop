반복 업무를 AI가 이해하고 실행할 수 있는 구조로 바꾸기 위한 이론형 가이드입니다. 실습자료가 빈칸을 채우는 자료라면, 이 전자책은 왜 그런 구조가 필요한지 설명하는 자료입니다.

이 자료의 목적

AI에게 단발성 답변을 요청하는 수준을 넘어, 자료 / 기준 / 결과물 / 실행 절차가 분리된 업무 환경을 설계하는 방법을 설명합니다. 특히 Markdown, CLAUDE.md, reference 문서, command 파일이 각각 어떤 역할을 하는지 중심으로 정리했습니다.

Chapter 01

AI에게 일을 맡긴다는 것은
업무 환경을 설계한다는 뜻입니다.

많은 사람이 AI를 사용하지만, 실제 업무 효율이 크게 바뀌지 않는 이유는 단순합니다. AI에게 질문은 했지만, 일을 할 수 있는 환경은 만들어주지 않았기 때문입니다.

“회의록 정리해줘”, “보고서 초안 써줘”, “문의 답변 만들어줘” 같은 요청은 빠릅니다. 하지만 매번 자료를 다시 설명해야 하고, 양식과 톤이 흔들리며, 결과물이 다음 업무의 기준으로 남지 않습니다. 이 상태에서는 AI가 업무 보조자가 아니라 일회성 답변 생성기에 가깝습니다.

AI 업무 구조화의 핵심은 사람이 하던 판단과 절차를 AI가 읽을 수 있는 문서와 폴더로 바꾸는 것입니다.
문제 1

맥락 단절

자료와 배경을 매번 새로 입력해야 합니다.

문제 2

기준 부재

좋은 결과물의 기준이 문서로 남아 있지 않습니다.

문제 3

자산화 실패

결과물이 다음 업무의 샘플이나 기준으로 이어지지 않습니다.

업무를 4개 요소로 나누기

요소질문폴더/파일
InputAI가 읽어야 할 원본 자료는 무엇인가?data/
CheckAI가 따라야 할 기준, 양식, 금지사항은 무엇인가?CLAUDE.md, reference/
OutputAI가 만들어야 할 결과물은 무엇인가?output/
Command반복 실행할 절차는 무엇인가?.claude/commands/
Chapter 02

MD 파일은 AI에게 읽히기 좋은
가벼운 업무 문서입니다.

MD 파일은 Markdown 형식으로 작성된 문서입니다. 워드나 PPT처럼 꾸미는 문서가 아니라, 제목 / 목록 / 표 / 코드블록처럼 구조가 명확한 텍스트 문서입니다.

AI는 화려한 디자인보다 명확한 구조를 더 잘 읽습니다. 그래서 업무 기준서, 체크리스트, 역할 정의, 실행 절차는 md 파일로 정리하는 것이 좋습니다. md 파일은 사람이 읽기에도 쉽고, Git이나 Claude Code 같은 개발/AI 도구 안에서도 다루기 쉽습니다.

MD 파일이 적합한 경우

  • 업무 기준을 문서로 남길 때
  • AI에게 역할과 원칙을 알려줄 때
  • 반복 실행 절차를 저장할 때
  • 검수 체크리스트를 만들 때

MD 파일이 덜 적합한 경우

  • 복잡한 디자인 편집이 필요한 문서
  • 법적 서식처럼 원본 형식이 중요한 문서
  • 엑셀 계산식이나 데이터 분석이 중심인 자료
  • 이미지 배치가 핵심인 발표 자료

Markdown 기본 문법

# 큰 제목 ## 중간 제목 ### 작은 제목 - 목록 1 - 목록 2 | 구분 | 내용 | |---|---| | Input | AI가 읽을 원본 자료 | | Check | AI가 따라야 할 기준 | ```text 폴더 구조, 명령어, 예시는 코드블록으로 정리합니다. ```
멘토 코멘트

MD 파일은 개발자만 쓰는 문서가 아닙니다. AI에게 업무를 맡기기 위해 기준과 절차를 명확하게 적는 실무 문서라고 이해하면 됩니다.

Chapter 03

CLAUDE.md는 프로젝트 안의
AI 업무 매뉴얼입니다.

CLAUDE.md는 Claude Code가 프로젝트 안에서 참고하는 기본 지침서입니다. 이 프로젝트에서 AI가 어떤 역할을 하고, 어떤 기준을 지키며, 어떤 행동을 하면 안 되는지 적어두는 파일입니다.

사람에게 일을 맡길 때도 “이 업무의 목적은 무엇인지”, “어떤 톤으로 작성해야 하는지”, “어떤 정보는 절대 외부에 쓰면 안 되는지”를 알려줘야 합니다. CLAUDE.md는 그 설명을 AI가 계속 참고할 수 있도록 프로젝트 안에 고정하는 문서입니다.

항목설명예시
역할AI가 어떤 업무 동료처럼 행동해야 하는지 정의멘토 운영을 보조하는 AI 업무 동료
업무 목표이 프로젝트가 줄이려는 비효율과 만들 결과물 정의반복 피드백 작성 시간을 줄이고 기준을 통일
기본 원칙항상 지켜야 할 판단 기준원본 자료에 없는 내용은 단정하지 않는다
금지사항AI가 하면 안 되는 행동최종 승인, 외부 발송, 민감정보 노출
출력 형식결과물을 어떤 구조로 낼지 정의요약 / 핵심 내용 / 확인 필요 / 다음 액션

CLAUDE.md 예시

# Mentor Operation OS ## 역할 너는 멘토 운영을 보조하는 AI 업무 동료다. ## 업무 목표 팀별 제출물을 읽고, 기준에 맞는 피드백 초안을 작성한다. ## 기본 원칙 - 따뜻하지만 모호하지 않게 작성한다. - 확인되지 않은 내용은 단정하지 않는다. - 최종 판단과 발송은 사람이 한다.

reference/는 세부 기준서 보관함입니다.

CLAUDE.md가 프로젝트 전체의 업무 매뉴얼이라면, reference/는 개별 업무의 세부 기준서입니다. 예를 들어 피드백 톤 가이드, 보고서 양식, 표현 금지어, 검수 체크리스트처럼 업무마다 달라지는 기준을 분리해 보관합니다.

Chapter 04

Command는 긴 프롬프트가 아니라
반복 가능한 업무 절차입니다.

command 파일은 매번 길게 설명하던 업무 요청을 절차로 저장한 파일입니다. “무엇을 읽고, 어떤 기준으로 판단하고, 어떤 순서로 처리하고, 어디에 저장할지”를 적습니다.

좋은 command는 똑똑한 질문이 아니라 업무 레시피에 가깝습니다. 같은 자료와 기준을 넣었을 때 비슷한 수준의 결과물이 반복해서 나와야 합니다.

좋지 않은 요청

“이 자료 보고 피드백 잘 써줘.”

자료 위치, 판단 기준, 출력 형식, 검수 지점이 없어 결과가 매번 달라질 수 있습니다.

좋은 command

data/ 제출물을 읽고 reference/ 기준에 맞춰 요약, 잘한 점, 보완점, 다음 액션, 확인 필요 사항 순서로 output/에 초안을 저장합니다.

command 파일 기본 구조

# feedback-draft ## 설명 팀 제출 자료를 바탕으로 멘토 피드백 초안을 작성한다. ## 입력 - data/team-submissions/ - reference/feedback-criteria.md - reference/mentor-tone-guide.md ## 처리 단계 1. 제출 자료의 핵심 내용을 요약한다. 2. 기준에 맞춰 잘한 점과 보완점을 분리한다. 3. 다음 액션 3개를 제안한다. 4. 확인이 필요한 내용을 별도로 표시한다.
Skill과 command의 관계

Skill은 반복 업무를 수행하는 기능 또는 역할로 이해하면 됩니다. command 파일은 그 Skill이 실행될 때 따를 절차서입니다. 즉, Skill이 업무 역할이라면 command는 업무 매뉴얼입니다.

Chapter 05

AI 구조화의 완성은
사람 검수 지점을 남기는 것입니다.

AI에게 일을 맡긴다는 것은 사람의 책임이 사라진다는 뜻이 아닙니다. 오히려 사람이 반드시 봐야 할 지점을 더 명확하게 표시하는 과정입니다.

특히 행정 업무에서는 사실관계, 수치, 개인정보, 외부 발송 여부, 최종 판단이 중요합니다. 이런 항목은 AI가 초안을 만들더라도 사람이 마지막에 확인해야 합니다.

검수 항목왜 필요한가예시
사실관계AI가 원문을 잘못 해석할 수 있음결정사항, 참석자, 일정
수치숫자 오류는 업무 신뢰도에 직접 영향예산, 인원, 기한, 점수
개인정보외부 노출 시 리스크가 큼이름, 연락처, 평가 내용
외부 발송문구 하나가 기관 입장으로 해석될 수 있음메일, 안내문, 공지
최종 판단승인과 결정은 사람이 책임져야 함합격/불합격, 예산 승인, 공식 답변
실무 적용 기준

처음부터 최종 발송이나 승인까지 자동화하지 않습니다. 첫 단계에서는 요약, 분류, 초안 작성, 누락 탐지처럼 사람이 검토하기 쉬운 구간부터 설계하는 것이 안전합니다.

최종 점검

반복 업무가 하나로 좁혀졌는가?
data / reference / output / commands가 구분되어 있는가?
CLAUDE.md에 역할, 원칙, 금지사항이 있는가?
command 파일의 입력 / 처리 / 출력이 연결되는가?
사람이 검수해야 할 지점이 분리되어 있는가?
오늘 하나만 기억한다면: 반복 업무는 자료 → 기준 → 결과물 → 실행 레시피로 구조화할 수 있습니다.
