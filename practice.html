AI 프로젝트 폴더 v1
만들기

반복 업무 하나를 골라 AI가 이해하고 실행할 수 있는 업무 구조 초안을 만드는 실습자료입니다. 완성된 자동화보다 먼저 자료, 기준, 결과물, 실행 절차를 분리하는 데 집중합니다.

오늘 만들 것

완성된 자동화 프로그램이 아니라, AI에게 업무를 인수인계할 수 있는 최소 구조입니다. 각 단계의 빈칸을 채우면 마지막에 하나의 프로젝트 폴더 초안이 완성됩니다.

01. Workshop Goal

오늘 멘토링의 목표

자동화 프로그램을 완성하는 시간이 아니라, 반복 업무 하나를 AI가 일할 수 있는 폴더와 Skill 초안으로 바꾸는 시간입니다.

시간파트목표산출물
0~5분오리엔테이션오늘 만들 산출물 이해실습 목표 확인
5~15분업무 선정반복 업무 1개로 좁히기업무명과 문제 정의
15~30분폴더 설계data, reference, output 구조 잡기프로젝트 폴더 v1
30~45분Skill 설계첫 command 파일 초안 만들기Skill 이름과 처리 단계
45~60분피드백과 공유위험도와 검수 지점 점검보완 포인트
MENTOR TIP

자동화보다 구조가 먼저입니다. AI에게 일을 맡기려면 사람이 하던 업무를 설명 가능한 구조로 바꿔야 합니다.

02. Concept Mapping

강의 개념과 실습 산출물 연결

강의에서 배운 Input, Check, Output, Command 개념을 실제 프로젝트 폴더로 옮깁니다.

강의 개념실습 산출물파일 또는 폴더
InputAI가 읽을 원본 자료 정의data
CheckAI가 따라야 할 기준, 양식, 원칙CLAUDE.md, reference
OutputAI가 남길 결과물 구조output
Repeat반복 실행할 업무 절차.claude commands
Human Check사람이 확인할 지점CLAUDE.md, command 검수 단계
폴더 설계란?

AI가 일할 때 필요한 자료, 기준, 결과물, 실행 절차의 위치를 정하는 일입니다. 단순 정리가 아니라 AI에게 업무 환경을 만들어주는 과정입니다.

MENTOR TIP

잘해줘는 기준이 아닙니다. 무엇을 보고, 어떤 기준으로, 어떤 형식의 결과물을 만들지 분리해야 반복 가능한 업무가 됩니다.

03. Step 1

반복 업무 1개 고르기

처음부터 팀 전체 업무를 잡지 않습니다. 반복되고, 자료가 남아 있고, 결과물이 명확한 업무 1개를 고릅니다.

작성 질문내 답변
Q1. 내가 자주 반복하는 업무는?
Q2. 가장 시간이 많이 걸리는 지점은?
Q3. 반복될 때 생기는 문제는?
Q4. AI 초안을 사람이 검토 가능한가?

좋은 주제 예시

  • 회의록 정리
  • 주간보고 취합
  • 문의 응대 초안
  • 사업공고 요약
  • 멘티 과제 피드백 작성

멘토 질문

  • 이 업무는 한 달에 몇 번 반복되나요?
  • 자료가 이미 존재하나요?
  • 결과물이 명확한가요?
  • AI가 만든 초안을 사람이 검토할 수 있나요?
MENTOR TIP

크게 잡으면 실패합니다. 팀 전체보다 반복 업무 1개부터 시작하는 것이 좋습니다.

04. Step 2

Input, Check, Output 뽑기

폴더를 만들기 전에 업무를 4개 요소로 나눕니다. 이 표가 이후 폴더 구조의 설계도가 됩니다.

구분질문내 업무 기준 작성
InputAI가 읽어야 할 자료는?
CheckAI가 따라야 할 기준은?
OutputAI가 만들어야 할 결과물은?
Human Check사람이 확인할 부분은?
구분예시
Input회의 녹취록, 회의 메모, 지난 회의록
Check회의록 양식, 액션아이템 정리 기준, 외부 공유 금지 기준
Output회의록 초안, 담당자와 기한 표, 공유 메일 초안
Human Check결정사항 사실 여부, 담당자 누락, 민감정보 포함 여부
MENTOR TIP

도구보다 문제가 먼저입니다. 시간이 오래 걸리는 지점, 기준이 흔들리는 지점, 같은 설명을 반복하는 지점이 좋은 후보입니다.

05. Step 3

프로젝트 폴더 구조 만들기

폴더 구조는 AI가 어디서 자료를 읽고 어떤 기준을 보고 어디에 결과물을 남길지 알게 만드는 업무 배치입니다.

project-name/ ├── CLAUDE.md ├── data/ ├── reference/ ├── output/ └── .claude/ └── commands/

내 폴더 구조 v1

내_프로젝트명/ ├── CLAUDE.md ├── data/ │ ├── __________________ │ ├── __________________ │ └── __________________ ├── reference/ │ ├── __________________ │ └── __________________ ├── output/ │ ├── __________________ │ └── __________________ └── .claude/commands/__________________.md
폴더넣는 것주의할 점
data회의 메모, 공고문, 평가서, 문의 내역기준서와 섞지 않습니다.
reference양식, 기준표, 체크리스트, 금지 표현사람의 암묵지를 문서로 바꿉니다.
output초안, 최종본, 검토 체크리스트다음 업무의 샘플로 재사용합니다.
06. Step 4

CLAUDE.md 초안 만들기

CLAUDE.md는 AI에게 주는 업무 인수인계서입니다. 프로젝트 전체의 역할, 원칙, 금지사항, 출력 방식을 고정합니다.

# [프로젝트 이름] ## 역할 너는 [업무명]을 보조하는 AI 업무 동료다. ## 업무 목표 이 프로젝트의 목표는 [반복 업무의 비효율]을 줄이고, [만들어야 할 결과물]을 일관된 기준으로 생성하는 것이다. ## 기본 원칙 - 원본 자료에 없는 내용은 단정하지 않는다. - 결과물은 초안이며, 최종 판단은 사람이 한다. - 민감정보는 임의로 노출하지 않는다. ## 사람 검수 지점 - 사실관계 - 수치 - 개인정보 또는 민감정보 - 외부 발송 여부
작성 항목내 초안
AI의 역할
업무 목표
AI가 반드시 지켜야 할 원칙 3개
MENTOR TIP

CLAUDE.md는 직무기술서에 가깝습니다. 역할, 원칙, 금지사항이 고정되어야 AI가 같은 기준으로 일할 수 있습니다.

07. Step 5

첫 번째 Skill 고르기

처음부터 전체 업무를 자동화하지 않습니다. 첫 번째 Skill은 가치가 크면서도 사람이 안전하게 검수할 수 있는 업무부터 고릅니다.

선정 기준확인 질문내 판단
반복성자주 반복되는가?
시간 절감시간이 많이 드는가?
자료 준비도AI가 읽을 자료가 있는가?
기준 명확성판단 기준을 문서로 쓸 수 있는가?
안전성사람이 검수하기 쉬운가?

첫 Skill 추천

  • 자료 요약
  • 분류
  • 초안 작성
  • 체크리스트 생성
  • 누락 탐지

첫 Skill 비추천

  • 최종 발송
  • 외부 고객 자동 응대
  • 합격 또는 불합격 판단
  • 예산 승인
  • 법적 판단
08. Step 6

command 파일 초안 만들기

command는 긴 프롬프트를 저장하는 파일이 아닙니다. 반복 업무의 실행 절차를 저장하는 파일입니다.

# [skill-name] ## 설명 [이 Skill이 처리하는 반복 업무를 한 줄로 설명합니다.] ## 입력 - data/[원본 자료] - reference/[기준 문서] ## 처리 단계 1. 원본 자료를 읽는다. 2. 핵심 내용을 추출한다. 3. 기준 문서에 맞춰 분류한다. 4. 출력 형식에 맞춰 초안을 작성한다. 5. 사람 검수 항목을 별도로 표시한다. ## 출력 - output/[결과물 폴더] ## 사람 확인 필요 - 사실관계 - 수치 - 개인정보 또는 민감정보 - 최종 발송 여부
MENTOR TIP

command는 업무 레시피입니다. 어떤 자료를 읽고, 어떤 기준으로 판단하고, 어떤 순서로 처리하고, 어떤 형식으로 출력할지 적습니다.

09. Sample

샘플 완성본: 면접 평가 통합 도우미

샘플 결과 리포트에서 도출된 폴더와 Skill 예시입니다. 교육생은 이 구조를 참고해 자신의 업무에 맞게 바꿉니다.

면접_평가_통합_도우미/ ├── CLAUDE.md ├── data/ │ ├── 평가서원본/ │ ├── 표준스키마.md │ ├── 직무기술서/ │ └── 과거사례/ ├── reference/ │ ├── 평가항목기준.md │ ├── 표현금지어.md │ └── 보고서양식.md ├── output/ │ ├── 후보자카드/ │ └── 검토체크리스트/ └── .claude/ └── commands/ └── 평가서통합.md
# 평가서통합 ## 설명 면접관별 평가서를 표준화하고 후보자별 통합 카드 초안을 작성한다. ## 입력 - data/평가서원본/ - data/표준스키마.md - reference/평가항목기준.md ## 처리 단계 1. 면접관별 평가서를 읽는다. 2. 후보자ID 기준으로 평가서를 묶는다. 3. 점수와 코멘트를 표준 스키마에 맞춰 정리한다. 4. 후보자별 강점 3개, 우려 3개, 총평 초안을 작성한다. 5. 편향 표현과 누락 항목을 체크리스트로 표시한다. ## 출력 - output/후보자카드/ - output/검토체크리스트/
10. Final Check

실습 완료 체크리스트

마지막으로 내 설계가 실제 실행 가능한 구조인지 확인합니다.

□ 반복 업무 1개를 골랐다
□ 업무의 문제를 한 문장으로 정의했다
□ Input, Check, Output을 나눴다
□ 프로젝트 폴더 이름을 정했다
□ data 폴더에 들어갈 자료를 정했다
□ reference 폴더에 들어갈 기준을 정했다
□ output 폴더에 쌓일 결과물을 정했다
□ CLAUDE.md 초안을 작성했다
□ 첫 번째 Skill을 골랐다
□ command 파일 초안을 작성했다
□ 사람이 검수해야 할 지점을 표시했다
마지막 한 문장

반복 업무는 자료, 기준, 결과물, 실행 레시피로 구조화할 수 있습니다. 중요한 것은 완벽한 자동화가 아니라 AI에게 인수인계 가능한 최소 구조를 만드는 것입니다.
